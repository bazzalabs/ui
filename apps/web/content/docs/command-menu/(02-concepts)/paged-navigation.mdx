# Paged Navigation

Command menus use **paged navigation** with a navigation stack, unlike action menus which use nested popovers. This design pattern is optimized for keyboard-driven workflows and provides a cleaner, more focused user experience.

## How It Works

When a user selects a submenu item, the command menu:

1. **Pushes** the submenu onto a navigation stack
2. **Replaces** the current view with the submenu content
3. **Shows breadcrumbs** indicating the current path
4. **Provides a back button** to return to the parent

```
Root Menu → Select "Settings" → Settings Menu → Select "Advanced" → Advanced Settings
[Home]                        [Home / Settings]                [Home / Settings / Advanced]
```

## Stack-Based Architecture

### Navigation Stack

The navigation stack is an array of entries representing the current path:

```typescript
type NavigationStackEntry = {
  menuId: string        // Unique identifier for the menu
  menuTitle?: string    // Display title for breadcrumbs
  parentMenuId?: string // Parent menu identifier
}
```

**Example navigation flow:**

```typescript
// At root
navigationStack: []

// After entering "Settings"
navigationStack: [
  { menuId: 'settings', menuTitle: 'Settings' }
]

// After entering "Advanced" submenu
navigationStack: [
  { menuId: 'settings', menuTitle: 'Settings' },
  { menuId: 'advanced', menuTitle: 'Advanced Settings' }
]
```

### Stack Operations

**Push (Navigate Forward)**
- User selects a submenu item
- Current query is cleared
- Submenu is pushed onto stack
- New menu content is displayed

**Pop (Navigate Back)**
- User clicks back button or presses Escape/Left arrow
- Current query is cleared
- Top item is popped from stack
- Parent menu content is displayed

**Clear (Close Dialog)**
- User closes the dialog
- Entire stack is cleared
- Returns to root state

## Advantages of Paged Navigation

### 1. Keyboard-First Design

Paged navigation is optimized for keyboard use:

- **No hover states** - Submenus don't open on hover
- **Clear selection** - Enter to go forward, Escape to go back
- **Linear flow** - One menu at a time, easier to navigate with arrow keys

### 2. Reduced Cognitive Load

- **Single focus** - Only one menu visible at a time
- **Clear context** - Breadcrumbs show where you are
- **No spatial relationships** - Don't need to track nested popovers

### 3. Mobile-Friendly

- **Full-screen menus** - Each page uses full available space
- **Touch-friendly** - Large tap targets, no hover required
- **Back button** - Familiar mobile navigation pattern

### 4. Consistent Layout

- **Fixed dimensions** - Dialog size doesn't change with nesting
- **Smooth transitions** - Height animates, content can slide
- **Predictable behavior** - Same navigation pattern at every level

## vs. Nested Popovers (Action Menu)

| Aspect | Paged Navigation (Command Menu) | Nested Popovers (Action Menu) |
|--------|--------------------------------|------------------------------|
| **Visual** | One menu at a time | Multiple menus stacked |
| **Navigation** | Stack-based (push/pop) | Tree-based (open/close) |
| **Keyboard** | Enter/Escape, arrow keys | Right arrow to open, Left to close |
| **Breadcrumbs** | Always shown (optional) | Not applicable |
| **Space** | Fixed dialog size | Grows with nesting |
| **Mobile** | Native-feeling | Requires careful positioning |
| **Use Case** | Global commands, search | Contextual actions |

## Creating Submenus

Define submenus using `kind: 'submenu'`:

```tsx
const menu = {
  nodes: [
    {
      kind: 'item',
      id: 'home',
      label: 'Go Home',
      onSelect: () => router.push('/')
    },
    {
      kind: 'submenu',
      id: 'settings',
      label: 'Settings',
      title: 'Settings Menu', // Shows in breadcrumbs
      nodes: [
        {
          kind: 'item',
          id: 'profile',
          label: 'Edit Profile',
          onSelect: () => openProfile()
        },
        {
          kind: 'submenu',
          id: 'advanced',
          label: 'Advanced',
          title: 'Advanced Settings',
          nodes: [
            {
              kind: 'item',
              id: 'api',
              label: 'API Keys',
              onSelect: () => openApiKeys()
            }
          ]
        }
      ]
    }
  ]
}
```

## Navigation Lifecycle

### Forward Navigation

1. **User interaction** - Clicks submenu item or presses Enter/Right arrow
2. **Query cleared** - Search input is reset to empty string
3. **onNavigationChange fires** - `direction: 'forward'` with breadcrumb state
4. **Stack updated** - New entry pushed onto navigation stack
5. **Menu re-renders** - New submenu content is displayed
6. **Input refocused** - Search input regains focus

### Backward Navigation

1. **User interaction** - Clicks back button, presses Escape, or Left arrow (when in submenu)
2. **Query cleared** - Search input is reset to empty string
3. **onNavigationChange fires** - `direction: 'back'` with breadcrumb state
4. **Stack updated** - Top entry popped from navigation stack
5. **Menu re-renders** - Parent menu content is displayed
6. **Input refocused** - Search input regains focus

### Dialog Close

1. **User interaction** - Clicks overlay, presses Escape (at root), or programmatic close
2. **onOpenChange fires** - `open: false`
3. **Stack cleared** - Navigation stack is emptied
4. **State reset** - Returns to root menu state

## Deep Dive: Menu State Management

### Current Menu Computation

The current menu is computed from the navigation stack:

```typescript
const currentMenu = useMemo(() => {
  if (navigationStack.length === 0) {
    return rootMenu // Show root menu
  }

  const currentEntry = navigationStack[navigationStack.length - 1]
  return submenuMap.get(currentEntry.menuId) ?? rootMenu
}, [rootMenu, navigationStack])
```

### Submenu Storage

Submenus are stored in a ref map to avoid re-creating them:

```typescript
const submenuMapRef = useRef<Map<string, MenuDef>>(new Map())

// When pushing
submenuMapRef.current.set(entry.menuId, submenu)

// When popping
const poppedEntry = navigationStack[navigationStack.length - 1]
submenuMapRef.current.delete(poppedEntry.menuId)
```

### Query Clearing

The query is cleared on navigation to provide a clean slate:

```typescript
function pushSubmenu(entry, submenu) {
  onQueryChange?.('') // Clear query first
  // ... push logic
}

function popSubmenu() {
  onQueryChange?.('') // Clear query first
  // ... pop logic
}
```

This ensures users don't see stale search results when navigating.

## Best Practices

### 1. Use Descriptive Titles

```tsx
// ❌ Bad - label and title are the same
{
  kind: 'submenu',
  label: 'Settings',
  title: 'Settings'
}

// ✅ Good - title provides context
{
  kind: 'submenu',
  label: 'Settings',
  title: 'Settings Menu'
}
```

### 2. Limit Nesting Depth

While paged navigation supports unlimited nesting, limit to 2-3 levels for best UX:

```
✅ Good:  Root → Category → Action
✅ OK:    Root → Category → Subcategory → Action
⚠️  Avoid: Root → L1 → L2 → L3 → L4 → Action
```

### 3. Group Related Commands

Use groups within submenus to organize related commands:

```tsx
{
  kind: 'submenu',
  label: 'File',
  nodes: [
    {
      kind: 'group',
      heading: 'New',
      nodes: [
        { kind: 'item', label: 'New File' },
        { kind: 'item', label: 'New Folder' },
      ]
    },
    {
      kind: 'group',
      heading: 'Recent',
      nodes: [
        { kind: 'item', label: 'recent1.txt' },
        { kind: 'item', label: 'recent2.txt' },
      ]
    }
  ]
}
```

### 4. Provide Clear Back Navigation

Always enable breadcrumbs unless you have a specific reason not to:

```tsx
// ✅ Default - breadcrumbs shown
<CommandMenu menu={menu} />

// ⚠️ Only hide if you have custom navigation UI
<CommandMenu menu={menu} showBreadcrumbs={false} />
```

### 5. Handle Empty Submenus

Show helpful messages for empty submenus:

```tsx
{
  kind: 'submenu',
  label: 'Recent Files',
  nodes: recentFiles.length > 0 ? recentFiles : [
    {
      kind: 'item',
      id: 'empty',
      label: 'No recent files',
      disabled: true
    }
  ]
}
```

## Animation Opportunities

Paged navigation creates natural animation opportunities:

```tsx
<CommandMenu
  menu={menu}
  onNavigationChange={({ direction }) => {
    if (direction === 'forward') {
      // Slide left (new content comes from right)
      triggerAnimation('slide-left')
    } else {
      // Slide right (going back)
      triggerAnimation('slide-right')
    }
  }}
/>
```
