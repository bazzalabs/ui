# createCommandMenu

The `createCommandMenu` factory function creates a command menu component with pre-configured theme defaults. Perfect for design systems where you want consistent styling across all command menus.

## Signature

```typescript
function createCommandMenu<T = unknown>(
  options?: CreateCommandMenuOptions<T>
): CreateCommandMenuResult<T>
```

## Parameters

### CreateCommandMenuOptions

```typescript
type CreateCommandMenuOptions<T = unknown> = {
  /** Default slot components */
  slots?: Partial<CommandMenuSlots<T>>
  /** Default HTML attributes for slots */
  slotProps?: Partial<MenuSlotProps>
  /** Default CSS classes */
  classNames?: Partial<CommandMenuClassNames>
}
```

## Return Value

```typescript
type CreateCommandMenuResult<T> = React.FC<CommandMenuOptions<T>> & {
  Root: typeof CommandMenuRoot
  Trigger: typeof CommandMenuTrigger
  Content: typeof CommandMenuContent
  Input: typeof CommandMenuInput
  List: typeof CommandMenuList
  Breadcrumbs: typeof CommandMenuBreadcrumbs
}
```

Returns a **command menu component** with:
- Default `CommandMenu` convenience component
- Individual components as properties (Root, Trigger, Content, etc.)
- Factory-level theme applied to all instances

## Basic Usage

### Create with Defaults

```tsx
import { createCommandMenu } from '@bazza-ui/command-menu'

const { CommandMenu } = createCommandMenu({
  classNames: {
    dialogOverlay: 'bg-black/50 backdrop-blur-sm',
    dialogContent: 'bg-white dark:bg-gray-900 rounded-lg shadow-xl max-w-2xl',
    input: 'border-b border-gray-200 px-4 py-3',
    item: 'px-4 py-2 hover:bg-gray-100 rounded-md',
  },
})

// All instances use these defaults
export { CommandMenu }
```

### Use in Your App

```tsx
import { CommandMenu } from '@/components/command-menu'

function App() {
  return <CommandMenu menu={menu} />
}
```

## Three-Level Theming

The factory enables a three-level theming hierarchy:

### Level 1: Factory (Global)

Set once at factory creation:

```tsx
const { CommandMenu } = createCommandMenu({
  classNames: {
    item: 'px-4 py-2', // Base padding
  },
})
```

### Level 2: Instance

Override per component:

```tsx
<CommandMenu
  menu={menu}
  classNames={{
    item: 'hover:bg-blue-100', // Adds to factory defaults
  }}
/>
```

### Level 3: Surface (Menu/Submenu)

Override per menu:

```tsx
const menu = {
  theme: {
    classNames: {
      item: 'text-sm', // Adds to instance + factory
    },
  },
  nodes: [...],
}
```

### Merging Behavior

Classes **concatenate** across levels:

```tsx
// Factory: 'px-4 py-2'
// Instance: 'hover:bg-blue-100'
// Surface: 'text-sm'
// Result: 'px-4 py-2 hover:bg-blue-100 text-sm'
```

## With Custom Slots

Set default slot implementations:

```tsx
const { CommandMenu } = createCommandMenu({
  slots: {
    DialogInner: ({ children, baseProps }) => (
      <div {...baseProps} className="animate-fade-in">
        {children}
      </div>
    ),
    Header: () => (
      <div className="company-header">
        <Logo /> MyApp Commands
      </div>
    ),
    Footer: ({ menu }) => (
      <div className="company-footer">
        {menu.nodes.length} commands • Press ? for help
      </div>
    ),
  },
})
```

## With Default Loader Adapter

Pre-configure the loader adapter:

```tsx
import { ReactQueryLoaderAdapter } from '@bazza-ui/command-menu/loaders/tanstack-query'
import { LoaderAdapterProvider } from '@bazza-ui/command-menu'

const { CommandMenu: CommandMenuBase } = createCommandMenu({
  classNames: {...},
})

// Wrap with loader adapter
export function CommandMenu(props: ComponentProps<typeof CommandMenuBase>) {
  return (
    <LoaderAdapterProvider adapter={ReactQueryLoaderAdapter}>
      <CommandMenuBase {...props} />
    </LoaderAdapterProvider>
  )
}
```

## TypeScript

Full generic support:

```tsx
type AppData = {
  id: string
  label: string
  icon: React.ReactNode
  action: () => void
}

const { CommandMenu } = createCommandMenu<AppData>({
  slots: {
    Item: ({ node, bind }) => (
      <button {...bind.getItemProps()}>
        {node.data.icon}
        <span>{node.data.label}</span>
      </button>
    ),
  },
})

// Now all menus are typed with AppData
<CommandMenu<AppData> menu={menu} />
```

## Compound Component Pattern

The factory returns individual components for advanced composition:

```tsx
import { createCommandMenu } from '@bazza-ui/command-menu'

const { Root, Trigger, Content, Input, List, Breadcrumbs } = createCommandMenu({
  classNames: {...},
})

function CustomCommandMenu() {
  const [open, setOpen] = useState(false)
  const [query, setQuery] = useState('')

  return (
    <Root open={open} onOpenChange={setOpen} menu={menu}>
      <Trigger shortcut="cmd+k">
        <button>Open Menu</button>
      </Trigger>

      <Content>
        {/* Custom header */}
        <div className="custom-header">Search Commands</div>

        <Breadcrumbs />

        <Input
          value={query}
          onValueChange={setQuery}
          placeholder="Type to search..."
        />

        {/* Custom middle section */}
        <div className="help-text">
          Use ↑↓ to navigate, Enter to select
        </div>

        <List query={query} onQueryChange={setQuery} />

        {/* Custom footer */}
        <div className="custom-footer">
          <kbd>Esc</kbd> to close
        </div>
      </Content>
    </Root>
  )
}
```

### Animated Command Menu

```tsx
export const { CommandMenu } = createCommandMenu({
  slots: {
    DialogInner: ({ children, baseProps }) => {
      const [direction, setDirection] = useState<'forward' | 'back' | 'idle'>('idle')

      return (
        <div
          {...baseProps}
          className={cn(
            baseProps.className,
            direction === 'forward' && 'animate-slide-left',
            direction === 'back' && 'animate-slide-right'
          )}
        >
          {children}
        </div>
      )
    },
  },
})
```

## Best Practices

1. **Create once per design system** - One factory per app or library
2. **Export from centralized location** - e.g., `@/components/command-menu`
3. **Use compound components for customization** - When you need more control
4. **Set sensible defaults** - Make the 80% case work out of the box
5. **Document your defaults** - Help users understand what's pre-configured
6. **Version your factory** - If defaults change, consider versioning
