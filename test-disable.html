Test Instructions

  1. Go to your Next.js app
  2. Navigate to a page with the DropdownMenu.ControlDisable example
  3. Open browser console (F12)
  4. Click the "Disable Menu" button
  5. Check console for debug logs showing:
    • [DropdownMenuControl] disable() called
    • [DropdownMenuRoot] Control state updated
    • [DropdownMenuContent] Control state
    • [Surface] Control state
    • [PopupMenuItem] Control state (for each item)
    • [PopupMenuSubmenuTrigger] Disabled state check
  6. Open the menu and verify items are disabled (should not respond to clicks/hovers)

Expected Debug Output

When you click "Disable Menu":
1. [Demo] Toggle disabled, current state: { isDisabled: false, ... }
2. [DropdownMenuControl] disable() called
3. [DropdownMenuRoot] Control state updated: { disabled: true, ... }
4. [Demo] After disable: { disabled: true, ... }

When menu is opened:
5. [DropdownMenuContent] Control state: { hasControl: true, disabled: true, ... }
6. [Surface] Control state: { hasControl: true, disabled: true, ... }
7. [PopupMenuItem] Control state: { hasControl: true, disabled: true, ... } (for each item)
8. [PopupMenuSubmenuTrigger] Disabled state check: { menuDisabled: true, finalDisabled: true, ... }

What to Look For

If any of these logs show disabled: false when it should be true, that's where the problem is!

Common Issues

  • If control is null or undefined at any level, the control isn't being passed through
  • If disabled doesn't update after calling disable(), the state isn't being set correctly
  • If items still respond to clicks when disabled, the disabled prop isn't being applied to the DOM
